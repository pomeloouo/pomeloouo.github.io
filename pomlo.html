Pomlo

打開瀏覽器，就能操作機械手臂、相機與夾爪。

Pomlo 是我（林泓佑）獨立開發的網頁化機械手臂控制平台。它把手臂控制、教點、堆棧規劃與視覺定位整合在同一個網頁裡，讓現場人員不用在多套原廠軟體之間切換。

共 10 個正式版本，目前 v1.3.4

為什麼要做 Pomlo

當業務工程師時，我在客戶現場一再看到同樣的問題：設備本身沒問題，卡住的是「操作」。

原本的現場

  • 手臂、相機、夾爪各有一套原廠軟體，切來切去
  • 堆棧點位要一格一格手動教，換箱子尺寸就重來
  • 程式只有原廠工程師看得懂，現場人員不敢改
  • 斷網或暫停後狀態不明，只能整套重開

用 Pomlo 之後

  • 一個瀏覽器畫面連線所有設備，狀態即時更新
  • 教完四角，堆棧位置自動算，2D／3D 先看過再跑
  • 積木式程式，流程一眼看得懂，現場也能調整
  • 心跳偵測斷線、停止暫停立即生效，問題有提示

系統架構

四層分工，每一層都可以單獨重啟、單獨除錯。

前端

瀏覽器介面

Vue 3、Pinia、Blockly。程式編輯、教點、堆棧、視覺都在這裡操作。

WebSocket

Pomlo Server

Node.js、Fastify。執行程式、管理外掛，把設備狀態即時推給畫面。

HTTP、心跳

Pomlo Gateway

C# 設備驅動橋。由伺服器自動啟動與管理，讀取逾時不會卡死。

原廠 SDK、XML-RPC

現場設備

協作機械手臂、工業相機、夾爪與吸盤，以驅動外掛方式接入。

功能模組

PLTZ 棧板堆疊外掛

教四角定位棧板，自動排箱並檢查間距與支撐；2D 排箱圖與 3D 疊層檢視；外圈箱子標籤自動朝外；放料時第 6 軸自動判斷正反轉，轉不到的位置會標示出來。

陣列取放外掛

料盤陣列取放，「整片做完」積木一次跑完；進度視窗即時顯示，切頁回來已完成的格子不會遺失。

Eyso 視覺外掛

工業相機取像、樣板比對（旋轉框、遮罩、多外觀）、手眼相機校正與視覺夾取；到不了的角度會自動改成反向夾取。

積木式程式編輯

移到點位、從點位偏移、夾放、IO、變數等積木，可設速度與加速度；每支程式有自己的資料，互不干擾。

操作與教點

寸動教點，世界座標與關節角互相換算；法蘭轉接板與工具 TCP 設定；IO 表可自訂名稱與實際腳位。

安全與穩定

停止與暫停立即生效、全域速度執行中即時調整、上下使能開關、手臂工作區範圍、警報列、同一台電腦只能開一個 Pomlo，避免兩個畫面互相覆蓋設定。

實際畫面

一次真實的除錯

做給現場用的軟體，難的不是功能，而是出事的時候。

拔掉網路線之後，整個 Gateway 沒有回應

測試時手臂停在暫停狀態，接著網路線被拔掉。畫面隨即顯示「設備驅動橋沒有回應」，重開也一樣卡住。

追下去發現是一連串連鎖反應：暫停中的動作佔住驅動的鎖，伺服器每秒讀狀態，讀取逾時後又同步重讀，執行緒越堆越多，最後整個 Gateway 被塞滿。重開後，控制器還停在當時被暫停的動作，連線握手就不回應。

  1. 先恢復現場：直接查控制器狀態，確認手臂沒在動後送出停止指令，Gateway 重開即連上。
  2. Gateway 先開服務：設備改在背景連線，不再因為一台設備卡住整個程式。
  3. 讀取不再堆積：每台設備同時只有一個讀取，逾時就回最後一次的結果。
  4. 驅動偵測斷線：定時探測，連續失敗即判定斷線，並停止該手臂的程式。
  5. 連線前先清狀態：開啟時若上次動作沒結束，先送停止再連線。

常見問題

Pomlo 是誰開發的？

由林泓佑獨立開發。從需求定義、系統架構、C# 設備驅動、Node.js 伺服器、Vue 介面到實機測試與版本發佈，全部一人完成。

Pomlo 能做什麼？

用瀏覽器連線機械手臂、工業相機與夾爪；以積木編寫手臂流程；教導點位；規劃棧板堆疊與陣列取放；用樣板比對做視覺定位與夾取。

Pomlo 用什麼技術？

C# Gateway 負責設備驅動，Node.js（Fastify）伺服器負責程式執行與 WebSocket 推播，前端使用 Vue 3、Pinia 與 Blockly。
